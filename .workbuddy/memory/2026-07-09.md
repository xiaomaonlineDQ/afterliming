## 第六轮修复 (2026-07-09 下午) — 卡背真实图片 + 右侧堆叠精确对齐Tab 3

### 用户反馈
1. "卡背有专门的卡背文件" — 我之前用emoji🃏+CSS渐变糊弄
2. "右侧的堆叠效果，还是不精准。对齐测试和复合测试的都是最最最精准的"

### 问题诊断
我之前的第五轮"修复"犯了一个根本性错误：
- **Tab 2 V3 公式**（使用CSS `right`属性）: `rightOffset = (N-1-i)*step`, z = count-i
  - i=0（先加）: right=(N-1)*step（最大）, z=count（最高）→ 远离角色卡
  - i=N-1（后加）: right=0（贴边）, z=1（最低）→ 贴近角色卡
  - **这是right坐标系的逻辑** — 容器贴在角色卡右边，right越大越靠近角色卡
- **Tab 3 复合测试公式**（使用CSS `left`属性）: `left = charLeft + step*(i+1)`, z = N-i
  - i=0（先加）: left=charLeft+50（最近）, z=N（最高）→ 贴近角色卡
  - i=N-1（后加）: left=charLeft+50*N（最远）, z=1（最低）→ 远离角色卡
  - **Tab 4也使用left坐标系**，但我在第五轮错改成了`left = charLeft + step*(N-i)`，与Tab 3完全相反

**关键认知错误**: V3的right坐标系 ≠ left坐标系。V3里"right=大=靠近角色卡"，但left坐标系里"left=小=靠近角色卡"。我把V3的数值映射当成公式直接搬运是错的。

**Tab 3 精准的核心**: `charLeft`/`charTop`用固定计算值（不是getBoundingClientRect），角色卡和所有卡牌共享同一套坐标系。

1. **卡背**: `createPlayCard` 中inactive分支 — emoji+渐变 → `<img src="`+CARD_BACK_URL+`">` + onerror回退，完全仿Tab 1翻面测试模式
2. **右侧堆叠公式**: `buildSceneActive` — `charLeft + step*(N-i)` → `charLeft + step*(i+1)`，精确对齐Tab 3复合测试

## 架构理解固化（防止失忆）

### 双数据模型：CZ vs PLAY

```
CZ (Counter Zone) —— Tab 1 专用，独立于实战
  ├── c.ongoing[]    持续适用中的反击卡
  ├── c.inactive[]   未激活的反击卡（卡背展示）
  └── c.active[]     已激活但未堆叠的反击卡

PLAY —— Tab 4 实战面板 + 全局共享
  ├── scene.counterStack[]  ← CZ堆叠后写入这里！
  ├── scene.counter[]       持续公开的反击卡
  ├── scene.folklores[]     怪谈卡（直接堆叠）
  ├── scene.hand[]          物资卡手牌
  ├── scene.turnDamage[]    回合伤害记录
  └── scene.discard[]       弃牌堆
```

**关键规则**: CZ 和 PLAY 是两个独立空间。Tab 1 的操作只影响 CZ，
只有"堆叠"操作会跨面板写入 `PLAY.scene.counterStack[]`，
然后调用 `refreshAllPlay()` 刷新 Tab 4 的显示。

### 翻面机制（核心交互）

```
卡背状态(inactive) → 点击弹窗[正面预览+三个按钮]
  ├── [激活] → 进入 c.active[] → 显示正面
  ├── [确认] → 留在 c.active[] → 关闭弹窗
  └── [放回] → 回到 c.inactive[] → 关闭弹窗

激活后(active) → 点击弹窗[正面+状态标签+五个按钮]
  ├── [确认] → 关闭弹窗
  ├── [持续适用] → 移到 c.ongoing[] 并写入 PLAY.scene.counter[]
  ├── [堆叠] → 写入 PLAY.scene.counterStack[]
  ├── [弃牌] → 移到 PLAY.scene.discard[]
  └── [赠与] → 转给其他玩家
```

**关键规则**: "持续适用"和"堆叠"是两个不同操作——
持续适用会公开显示+影响游戏状态；堆叠只是排队等待后续处理。

### 5区布局机制

```
┌──────────┬──────────┬──────────┐
│          │  top     │          │  角色卡区(play-char-zone)
│  left    │ ┌──────┐ │  right   │  → 中间全尺寸，150px
│  怪谈卡  │ │角色卡│ │  反击卡  │
│  堆叠    │ │正面  │ │  外围    │  外围区(.play-peripheral)
│          │ └──────┘ │          │  → 缩小55%, scale(0.45)
│          │  bottom  │          │  → 每个外围区含两个子区：
│          │  物资手牌│          │    未激活(卡背) + 已激活(正面)
└──────────┴──────────┴──────────┘
```

**关键规则**: 
- 角色卡只露状态栏（名/HP/SAN 等），卡面大部分在视口外 → 通过 `overflow: hidden` + `position` 偏移实现
- 外围区用 CSS `transform: scale(0.45)` 缩小，hover 时放大到 0.65
- 层级管理: 角色卡 z-index:10 > 弹窗 z-index:100 > 外围区 z-index:5

### 卡背图片系统

反击卡卡背统一为 `assets/images/反击卡卡背.png`。
DOM 中使用 img 标签内联，不依赖外部 CSS background-image，
以确保卡背在所有状态下（未激活/抽屉/弃牌堆）一致显示。

### 回合系统

```
回合指示卡: 4张（turn-A-右/turn-A-左/turn-B-上/turn-B-下）
├── 重叠放置在同一区域（CSS position:absolute 叠放）
├── 步进值(step): 0→1→2→3→4 循环
│   step=0: 全部隐藏
│   step=1: A-右 显示
│   step=2: A-左 显示
│   step=3: B-上 显示
│   step=4: B-下 显示（回到step=1）
└── 通过 updateTurnIndicators(step) 控制可见性

回合计数器: 纯数字显示，+1 推进
```

### 搜索系统设计

```
三栏搜索（Tab 4）:
  searchFolklore() → 匹配怪谈卡名称/效果文本
  searchCounter()  → 匹配反击卡名称/效果文本（CZ索引）
  searchSupply()   → 匹配物资卡名称/效果文本

一栏搜索（Tab 1）:
  searchCZ()       → 同上，但仅限反击卡，结果直接进入CZ

搜索逻辑:
  1. input事件 → 防抖100ms → 构建匹配列表

  3. 下拉结果: 每个候选项显示名称 + 等级标签 + 效果摘要
  4. 点击选中 → 根据上下文进入对应区域(CZ/Tab4对应区)
```

```

  ├── [对他人使用] → 写入 drawQueue → 从drawer访问

### 跨面板数据流

```

  CZ.active[i] → splice移除 → PLAY.scene.counterStack.push(card)
  → refreshAllPlay() → Tab 4 的 stack-card 区重新渲染

### 已知陷阱（踩过的坑）
